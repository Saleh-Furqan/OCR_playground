# 6. OCR Integration and Receipt Parsing

## 6.1 OCR Research Project Overview

The OCR integration for ReTouch represents a comprehensive research initiative to enable intelligent receipt parsing and automated data extraction. This work was conducted as part of the Fall 2025 semester in a separate research repository located at /home/saleh/FYP/OCR_playground. The project compares three distinct approaches to receipt OCR evaluating accuracy, latency, and reliability trade-offs to determine the optimal solution for production deployment.

The primary research question explores which approach provides the best balance of accuracy, speed, and reliability for receipt processing: traditional OCR plus text language models, pure vision language models, or a hybrid approach combining both techniques. This question emerged from observing that traditional OCR engines like Tesseract struggle with poor image quality and varying layouts, while newer vision language models offer promising capabilities but with unclear performance characteristics and potentially high computational costs.

The OCR research project implements three complete approaches each representing a different strategy for extracting structured data from receipt images. The first approach uses traditional OCR engines including PaddleOCR and Tesseract to extract raw text from images, then passes this text to LLama 3.1 8B text language model to structure the data into JSON format with fields for merchant name, date, time, and total amount. The second approach uses Qwen2.5-VL 7B vision language model exclusively, feeding receipt images directly to the model and prompting it to extract structured data without any intermediate OCR step. The third hybrid approach combines PaddleOCR for text extraction with Qwen2.5-VL for validation and error correction, attempting to leverage the speed of traditional OCR with the intelligence of vision models.

All three approaches were benchmarked on the SROIE dataset which contains 626 receipt images from real-world retail environments. The SROIE dataset was released as part of the ICDAR 2019 competition on Scanned Receipts OCR and Information Extraction and has become a standard benchmark in receipt processing research. The dataset includes receipts from various merchants with different layouts, fonts, and image quality levels, providing a realistic test of OCR system robustness.

## 6.2 OCR Engine Evaluation

The OCR research evaluated multiple OCR engines with PaddleOCR emerging as the clear winner for receipt processing. PaddleOCR version 3.1 with the PP-OCRv5 model achieved 71.9 percent overall accuracy across all fields when benchmarked on the full 626-receipt SROIE dataset. This represents a significant 19.3 percentage point improvement over Tesseract which achieved only 52.6 percent overall accuracy on the same dataset.

PaddleOCR demonstrated particularly strong performance on critical financial fields. Amount extraction achieved 98.7 percent accuracy making it suitable for automated financial processing with minimal human review. This near-perfect accuracy on amounts is crucial for ReTouch's use case as incorrect amounts could cause serious problems in expense reporting and accounting workflows. Date extraction achieved 90.3 percent accuracy which is reliable enough for automated workflows while merchant name extraction achieved 80.3 percent accuracy indicating some manual review may be needed for merchant field.

The superior performance of PaddleOCR stems from several architectural improvements in the PP-OCRv5 model released in 2025. According to PaddlePaddle's release notes, PP-OCRv5 achieves a 13-point accuracy gain over the previous PP-OCRv4 version through improved handwriting recognition and support for multiple text types. The research identified several best practices for configuring PaddleOCR for receipt processing including enabling textline orientation classification to handle rotated text, configuring appropriate detection thresholds for small text, and using the modern PaddleX 3.x predict API rather than the deprecated ocr API.

Tesseract was evaluated as a budget-friendly alternative achieving 52.6 percent overall accuracy. While significantly less accurate than PaddleOCR, Tesseract has important advantages including zero licensing costs as it is fully open source, very low memory footprint making it suitable for resource-constrained environments, and 100 percent success rate meaning it never crashes or fails to return results even on challenging images. For deployments where cost is paramount and moderate accuracy is acceptable, Tesseract remains a viable option.

EasyOCR was also evaluated but showed intermediate performance between Tesseract and PaddleOCR without offering compelling advantages over either. The research concluded that for production deployment, PaddleOCR should be the primary choice with Tesseract as a fallback for specific use cases requiring minimal resource usage.

## 6.3 Vision Language Model Evaluation

The vision language model evaluation tested Qwen2.5-VL 7B which is an open-source multimodal model capable of understanding both images and text. The model was deployed locally using Ollama which provides a simple interface for running large language models on local hardware. Vision language models represent a fundamentally different approach to receipt OCR as they process the image directly without requiring a separate OCR step to extract text first.

Qwen2.5-VL achieved approximately 50 percent accuracy on the SROIE benchmark when running on CPU hardware. However, the model suffered from a 40 percent failure rate where it crashed or failed to produce valid output. These failures were primarily caused by insufficient memory when processing high-resolution images and timeout issues as the model took excessive time for inference on CPU. The failures highlight that vision language models require careful resource management and are currently better suited for GPU-accelerated environments.

Despite the stability issues, when Qwen2.5-VL successfully processed a receipt, it often produced high-quality structured output. The model demonstrated understanding of receipt structure and could extract multiple fields simultaneously from a single image. This suggests that with appropriate GPU hardware and stability improvements, vision language models could achieve accuracy exceeding traditional OCR approaches.

The research identified several best practices for using vision language models for receipt OCR through extensive experimentation and review of recent literature. Prompts should explicitly request JSON format output with the specific schema structure provided in the prompt. The temperature parameter should be set to zero for deterministic output ensuring the model produces consistent results rather than varying interpretations. The context window should be configured to 8192 tokens for vision tasks to accommodate both the image tokens and the structured output. Images should be preprocessed to JPEG quality of at least 95 to preserve text clarity as compression artifacts significantly degrade OCR accuracy.

The maximum image size parameter in Ollama defaults to 1024 pixels but should be increased to 1536 pixels for OCR tasks. The research found that receipts often contain small text that becomes illegible when downscaled to 1024 pixels but remains readable at 1536 pixels. This parameter adjustment alone improved accuracy by several percentage points in preliminary tests.

## 6.4 Hybrid Approach Design

The hybrid approach attempts to combine the speed and reliability of traditional OCR with the intelligence of vision language models. The design uses PaddleOCR as the primary extraction engine due to its high accuracy and fast processing time. For receipts where PaddleOCR returns results with low confidence scores, the system routes the image to Qwen2.5-VL for secondary processing.

The confidence-based routing logic examines the quality scores returned by PaddleOCR for each detected text region. If the average confidence across all regions exceeds a threshold such as 0.85, the system proceeds with the PaddleOCR results and passes the extracted text to LLama 3.1 for structuring. If the confidence is below the threshold indicating the receipt may have challenging characteristics like poor image quality or unusual layouts, the system invokes Qwen2.5-VL to process the original image.

This approach aims to achieve accuracy close to pure vision models while maintaining the speed advantage of traditional OCR for the majority of receipts. In theory, if 80 percent of receipts can be processed with high-confidence PaddleOCR taking perhaps 2 seconds per receipt, and only 20 percent require the slower vision model taking perhaps 30 seconds per receipt, the average latency would be approximately 7.6 seconds compared to 30 seconds for pure vision approach.

However, the hybrid approach introduces additional complexity including maintaining two separate processing pipelines, implementing reliable confidence scoring and routing logic, and handling cases where both approaches fail or disagree. The research implementation validated the core concept but identified that production deployment would require significant engineering work to handle edge cases robustly.

## 6.5 Structured Data Extraction

All three approaches ultimately produce structured JSON output containing key receipt fields. The target schema includes merchant name as a string containing the business name, date as a string in ISO 8601 format such as 2025-11-17, time as a string in 24-hour format such as 14:30:00, and total amount as a float representing the total purchase amount in dollars or the local currency.

For the OCR plus text LLM approach, structuring is handled by LLama 3.1 8B which receives the raw OCR text and a detailed system prompt. The system prompt describes the expected JSON schema and provides examples of properly formatted output. The prompt instructs the model to extract only the four key fields and to use null for any fields that cannot be identified in the text. Temperature is set to zero to ensure deterministic output rather than creative variations.

The text LLM approach has important limitations. It cannot correct errors introduced by the OCR engine, so if PaddleOCR misreads a merchant name as "Wall-Mart" instead of "Walmart", the LLM will output the incorrect text. The LLM also struggles when the OCR text contains significant jumbling such as when text from multiple columns is interleaved. Despite these limitations, the approach works well for the majority of receipts where OCR produces reasonably accurate text.

For the vision language model approach, Qwen2.5-VL receives the receipt image along with a prompt describing the extraction task. The prompt explicitly requests structured JSON output and provides the schema including field names and types. The model processes the image using its vision encoder which converts the image into token embeddings, then uses its language model to generate the JSON output token by token.

Vision models have the advantage of seeing the original image rather than text that may contain OCR errors. They can also use visual cues like text size and position to disambiguate fields. For example, the total amount is often printed in larger, bold text at the bottom of a receipt, which the vision model can recognize even if the specific text is slightly blurred. This spatial awareness allows vision models to potentially achieve higher accuracy than OCR-based approaches when properly configured and deployed.

## 6.6 Benchmark Results and Analysis

The comprehensive benchmarking on 626 receipts from the SROIE dataset provides statistically significant results to inform production deployment decisions. PaddleOCR plus LLama 3.1 text model emerged as the recommended approach achieving 71.9 percent overall accuracy with fast processing times and excellent stability. The 98.7 percent accuracy on amount extraction is particularly impressive and enables automated financial processing with minimal human review.

Tesseract plus LLama 3.1 achieved 52.6 percent overall accuracy which is acceptable for budget-constrained deployments or as a fallback when PaddleOCR is unavailable. Tesseract's perfect 100 percent success rate and minimal memory footprint make it valuable for reliability even if accuracy is lower.

Qwen2.5-VL vision model achieved approximately 50 percent accuracy but the 40 percent failure rate on CPU hardware makes it unsuitable for production deployment without significant infrastructure investment in GPU resources. The failures included system crashes from excessive memory consumption when processing high-resolution images, timeout errors when inference exceeded reasonable time limits, and occasionally malformed JSON output that could not be parsed.

The research identified that 11.7 percent of images in the SROIE dataset have dimensions exceeding 4500 pixels which caused system crashes due to memory exhaustion. Implementing image resizing before processing resolved most crashes but required careful tuning to maintain OCR accuracy while reducing memory consumption. Images were resized to maximum 3000 pixels on the longest edge which provided good balance between memory usage and text readability.

Latency analysis showed PaddleOCR processing takes approximately 1 to 3 seconds per receipt on CPU including OCR extraction and LLM structuring. Tesseract is even faster at under 1 second per receipt. Qwen2.5-VL on CPU took 20 to 60 seconds per receipt when it succeeded, making it impractical for high-throughput scenarios. With GPU acceleration, vision model inference could potentially be reduced to 2 to 5 seconds making it competitive with traditional approaches.

The cost analysis considered both computational resources and potential error costs. PaddleOCR requires minimal infrastructure as it runs efficiently on CPU and has modest memory requirements. The model itself is open source with no licensing fees. Qwen2.5-VL requires significant GPU memory and the higher computational cost must be weighed against the potential accuracy benefits. For ReTouch's initial deployment, the research recommends starting with PaddleOCR which provides excellent accuracy at low cost, with vision models reserved for future enhancements once user base and revenue justify GPU infrastructure investment.

## 6.7 Integration Architecture

The OCR subsystem has been designed as a separate microservice that can be deployed independently of the main ReTouch backend. This microservices architecture provides several benefits including independent scaling where the OCR service can be scaled based on processing demand without affecting the main API, technology isolation allowing different languages and frameworks optimized for OCR tasks, and fault isolation where OCR service failures do not cascade to other system components.

The proposed integration architecture has the main backend receiving receipt uploads and storing the raw image in S3 as currently implemented. After storing the image, the backend places a message on a job queue such as AWS SQS or Redis Queue containing the receipt identifier and S3 object key. The OCR worker service polls the queue for new jobs, downloads receipt images from S3, processes them through the chosen OCR pipeline, and writes the extracted structured data back to the PostgreSQL database in new tables.

The database schema extensions add a receipt_data table with foreign key to the receipts table containing fields for merchant name, transaction date, transaction time, total amount in cents to avoid floating point issues, and raw OCR confidence scores. An ocr_metadata table tracks processing information including which OCR engine was used, processing timestamp, latency in milliseconds, and any error messages or warnings. This metadata enables monitoring OCR performance and identifying problematic receipts that may need manual review.

The main backend API exposes new endpoints for accessing structured receipt data. A GET endpoint at /api/receipt/{receipt_id}/data returns the parsed fields as JSON. A PATCH endpoint allows users to correct any fields that were extracted incorrectly, maintaining the corrections in the database for future machine learning model training. A search endpoint enables filtering receipts by merchant name, date range, or amount range using the structured data.

Asynchronous processing through the job queue is essential because OCR takes several seconds per receipt and should not block the upload API response. Users receive immediate confirmation that their receipt was uploaded successfully and can view the image immediately using presigned URLs as currently implemented. The structured data appears within a few seconds once OCR processing completes, and the frontend can poll for updates or use websockets for real-time notifications.

## 6.8 Error Handling and Quality Assurance

Robust error handling is critical for production OCR deployment. The system implements multiple layers of validation and fallback strategies. Before OCR processing begins, images are validated to ensure they meet minimum quality requirements including resolution above 800 pixels on the shortest edge, file size under 10 megabytes to prevent memory issues, and valid MIME types of JPEG or PNG. Images failing validation are rejected with clear error messages explaining the requirements.

During OCR processing, the system monitors for common failure modes. If PaddleOCR crashes or times out, the system automatically retries with Tesseract as a fallback. If both traditional OCR engines fail, the receipt is marked as requiring manual processing and flagged for human review. Confidence scores from OCR engines are persisted and used to prioritize receipts for quality checking, with low-confidence extractions reviewed first.

After extraction, the structured data undergoes validation. Date strings are parsed to ensure they are valid dates and not nonsense text. Amounts are validated to be positive numbers in a reasonable range such as 0.01 to 10,000 dollars. Merchant names are checked against a database of known merchants to catch obvious OCR errors and suggest corrections. For example, if OCR extracts "Wa1-Mart" the system can suggest "Walmart" based on string similarity matching.

The frontend provides a manual correction interface allowing users to edit any field that was extracted incorrectly. These corrections are valuable for two reasons. First, they immediately improve data quality for the user's own records. Second, they can be used to fine-tune machine learning models in the future. By collecting corrections, ReTouch can build a training dataset of receipts with ground truth labels and potentially train custom OCR models optimized for the specific receipt formats common among ReTouch users.

Quality metrics are tracked in a monitoring dashboard including overall accuracy calculated from user corrections, per-field accuracy broken down by merchant, date, and amount, processing latency with percentiles to identify outliers, and failure rates indicating what percentage of receipts fail OCR. These metrics inform decisions about infrastructure scaling, algorithm improvements, and when to investigate systematic problems.

## 6.9 Future OCR Enhancements

Several enhancements to the OCR subsystem are planned for future development. The first priority is deploying vision language models on GPU infrastructure to enable higher accuracy processing. AWS offers GPU instances such as g4dn types with NVIDIA T4 GPUs that can accelerate Qwen2.5-VL inference to 2 to 5 seconds per receipt. This would make vision models practical for production use while achieving the 94 to 96 percent accuracy potential identified in research.

Fine-tuning custom models on ReTouch-specific data represents a significant opportunity. The SROIE dataset used for benchmarking contains generic retail receipts but ReTouch users may have specific merchant preferences or receipt formats. By collecting thousands of receipts with user corrections, ReTouch can fine-tune PaddleOCR or train custom models that learn the specific characteristics of receipts in the system. Research shows that domain-specific fine-tuning can improve accuracy by 10 to 15 percentage points.

Line item extraction would extend the current field extraction to capture individual items purchased along with their quantities and prices. This requires more sophisticated parsing as line items form a variable-length list rather than single fields. Vision language models show promise for line item extraction as they can understand tabular structure in receipts. This data would enable powerful features like analyzing which products are purchased most frequently, tracking price changes over time for specific items, and providing detailed expense categorization.

Multi-language support is essential for international expansion. PaddleOCR supports over 80 languages and could be configured to automatically detect and process receipts in different languages. The LLM structuring step would need prompts in multiple languages or use of multilingual models. Vision language models like Qwen2.5-VL have some multilingual capability although accuracy may vary by language.

Handwritten receipt support poses additional challenges as handwriting recognition accuracy remains lower than printed text recognition. However, some use cases involve handwritten receipts such as small businesses without electronic point-of-sale systems or receipts with handwritten notes. Advanced preprocessing including binarization and skew correction can improve handwritten text recognition. Vision models may also be particularly well-suited for handwriting as they can learn letter formation patterns.

Real-time processing feedback would improve user experience by showing OCR progress as it happens. Currently users upload a receipt and wait for processing to complete. With websocket connections, the frontend could display live updates such as "Extracting text", "Identifying merchant", and "Processing complete" giving users confidence that the system is working. This is especially important for slower vision model processing where users might otherwise think the system is frozen.

The OCR research project successfully demonstrated the feasibility of automated receipt parsing with excellent accuracy for critical financial fields. The systematic benchmarking on 626 receipts provides confidence that PaddleOCR-based approaches are production-ready and can handle real-world receipt variability. The modular architecture and comprehensive error handling ensure the system will be reliable and maintainable as ReTouch scales to thousands of users and millions of receipts.
